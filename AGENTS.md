# AGENTS.md

## Мова і стиль

- Завжди відповідай українською.
- Пиши коротко, конкретно і з прив'язкою до поточного коду.
- Не змінюй бізнес-правила мовчки. Якщо запит впливає на правила змін, грошей, інкогніто, backup/import/export або імпорт графіка, явно назви зміну перед реалізацією.
- Не додавай сервер, акаунти, хмарну синхронізацію або мережеву залежність без прямої вказівки користувача.

## Обов'язковий старт кожної сесії

1. Прочитай цей файл.
2. Прочитай `PROJECT_CONTEXT.md`.
3. Перевір поточний стан репозиторію і стек перед редагуванням.
4. Працюй з наявними патернами проєкту, а не переписуй архітектуру без потреби.

## Поточний проєкт

Це мобільний offline-first PWA для працівників підприємств. Додаток працює без акаунтів, серверів і синхронізації через інтернет. Усі дані мають залишатися локальними на пристрої користувача.

Поточний стек:

- React
- TypeScript
- Vite
- vite-plugin-pwa
- lucide-react
- Vitest

Корисні команди:

```bash
npm run build
npm run build:pages
npm test
npm run dev
```

## Пріоритети реалізації

- Offline-first поведінка важливіша за інтеграції.
- Локальна надійність даних важливіша за візуальні ефекти.
- Основна метрика додатку - гроші.
- Фінансова логіка, правила змін і імпорт/експорт мають бути покриті тестами, коли змінюється відповідна логіка.
- UI має бути мобільним, зрозумілим і швидким для щоденного використання на роботі.

## Непорушні правила домену

- Є дві планові зміни: `06:30-14:30` і `14:30-22:30`.
- Тип зміни визначається автоматично за найближчим плановим часом.
- Один календарний день має максимум одну зміну.
- Не може існувати більше однієї активної зміни.
- Кнопки `Прийшов` і `Пішов` мають спрацьовувати через утримання, а не випадковий тап.
- Відсоток виконання виробітку рахується від плану G1, якщо для завершеного тікета не задано ручний відсоток компанії; ручне значення має пріоритет у підсумках.
- Дані зберігаються локально.
- Режим інкогніто замінює фінансові показники на `••••` і блокує редагування грошових полів.
- Backup/import/export працює через JSON.
- Графік підприємства імпортується з локального PDF із текстовим шаром.

## Робота з кодом

- Перед змінами знайди релевантні файли через `rg` або `rg --files`.
- Не видаляй і не перезаписуй чужі зміни без прямого прохання.
- Не роби масштабний рефакторинг разом із маленькою функціональною зміною.
- Для UI дотримуйся наявного стилю, але перевіряй мобільну зручність.
- Після змін запускай найменший достатній набір перевірок. Для широких змін запускай `npm run build` і `npm test`.

## Публікація через ChatGPT Sites

- Після змін у репозиторії запусти потрібні перевірки, але не створюй коміт, не роби push і не запускай deploy без прямого прохання користувача.
- Конфігурація Sites зберігається у `.openai/hosting.json`, а production build має бути сумісним із Cloudflare Workers.
- `npm run build` створює Sites/Cloudflare Worker-збірку. `npm run build:pages` збережено лише для локальної перевірки замороженої legacy-версії з базовим шляхом `/Timer/`; її артефакти не можна публікувати.
- GitHub Pages заморожено на вже опублікованій версії: не створюй і не відновлюй Pages workflow, не завантажуй туди нові артефакти та не вимикай наявний Pages-сайт.
- Усі нові релізи публікуються лише через Sites окремим deployment-процесом; push у `main` не має оновлювати GitHub Pages.
- Якщо користувач прямо попросив виконати push або deploy, не публікуй зламану версію: у разі помилки тестів, збірки, push або deploy зупинись і явно повідом про причину.
